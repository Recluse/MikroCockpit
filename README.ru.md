# MikroCockpit

Нативный трей-контроллер для роутеров MikroTik RouterOS на macOS: статус в
меню-баре, окно дашборда на AppKit и опциональная локальная веб-панель.

MikroCockpit — это *пульт*, а не замена WinBox. Здесь частые операции: состояние
роутера, переключение VPN-выходов, прямой доступ на весь LAN или для одного
устройства, настройки внешнего вида. Редактирование конфигурации остаётся за
WinBox/WebFig.

> **Статус: v0.1, первый релиз. Это грубая первая версия.**
> Она сделана вокруг одного реального сетапа и честно говорит о своих границах,
> а не притворяется готовым продуктом. Прочитайте
> [Известные ограничения](#известные-ограничения) прежде чем полагаться на неё.
> Жду баг-репорты и патчи.

## Что работает

- **SSH с существующим ключом.** Строгая проверка `known_hosts`, без паролей в
  приложении и без автоматического принятия неизвестных ключей. Первое соединение
  с неизвестным роутером нужно вручную проверить обычным `ssh`.
- **Состояние роутера**: система, WireGuard-туннели, DHCP-lease'ы, маршруты
  выбранной таблицы, интерфейсы.
- **Выбор VPN-выхода** через REST-API mihomo/Clash; `DIRECT`, циклические и
  неизвестные группы запрещены.
- **Приоритет маршрутов** для существующих статических default-маршрутов в VPN-таблице;
  таблица `main` не изменяется.
- **Переключатели WireGuard** только для явно перечисленных туннелей; туннели из
  списка *protected* — только на чтение.
- **Исключения прямого доступа** (IPv4 destination list) и **прямой доступ
  для устройства / всего LAN**: 15 минут, час, постоянно. Последние два режима
  требуют установленной и проверенной политики MikroCockpit.
- **Локальная веб-панель** из меню — те же действия и состояние.
- **Настройка внешнего вида**: тёмная/светлая/системная тема, скрываемые блоки
  панели, порядок и состав разделов трее, подпись (выход, CPU, имя профиля или
  только иконка). Настройки сохраняются.

Mihomo необязателен: пустой `mihomo_url` полностью отключает интеграцию.

## Чем это не является

- Не заменой WinBox/WebFig: нет произвольного редактирования конфига и нет
  пропуска произвольных CLI-команд.
- Не менеджером VPN-провайдеров: приложение не создаёт WG-интерфейсы, ключи и
  peers.
- Не мультивендорным инструментом: только RouterOS 7 с `:serialize to=json`
  (проверено на 7.24.x). RouterOS 6 не поддерживается.

## Требования

- macOS 12+ (проверено на Apple Silicon; скрипт собирает под архитектуру хоста)
- Rust stable и Xcode Command Line Tools
- Роутер с RouterOS 7, доступный по SSH с ключом

## Сборка и запуск

```sh
git clone https://github.com/Recluse/MikroCockpit.git
cd MikroCockpit
cp settings.example.json settings.json   # заполнить свой профиль
./build.sh
open dist/MikroCockpit.app
```

Важно:

- `dist/settings.json` лежит **рядом с** `.app`, а не внутри подписанного bundle.
  Повторная сборка не перезаписывает существующий профиль.
- Состояние, настройки панели, lock и аудит-журнал — в `dist/state/`. Не разносить
  `.app` и профиль по разным папкам.
- Копирование в Applications, автозапуск, Developer ID и notarization **пока не
  настроены**; локальная сборка подписана ad-hoc. Gatekeeper может ругаться на
  скачанную версию — правый клик → Открыть, или собрать локально.
- Другой профиль: `MIKROCOCKPIT_CONFIG=/absolute/path/profile.json`.
- Токен mihomo **не хранится** в JSON: задайте `mihomo_secret_env` — имя переменной
  окружения с bearer token.

## Справочник профиля

`settings.example.json` — обезличенный пример.

| Поле | Значение |
|---|---|
| `host`, `user`, `identity` | SSH-адрес роутера и путь к ключу |
| `lan_cidrs` | Одна или несколько IPv4 LAN-сетей |
| `lan_interface_list` | Interface list со стороны LAN |
| `wan_interfaces` | WAN-интерфейсы (члены списка WAN приложения) |
| `route_table` | VPN-таблица маршрутов под управлением |
| `bypass_list` | Address list назначений, которые идут напрямую |
| `managed_wireguard` | Туннели, которыми можно управлять |
| `protected_wireguard` | Туннели только для просмотра |
| `extra_direct_rules` | Дополнительные IPv4-исключения: адрес, протокол, порты |
| `mihomo_url`, `mihomo_group` | Опциональный API mihomo (пусто = отключено) |
| `poll_seconds` | Интервал опроса, 5…300 |
| `tray_*`, `status_*` | Внешний вид трее и строки статуса |

На роутере должны уже существовать выбранная VPN-таблица и LAN mark-routing с
`dst-address-list=!<bypass_list>` — приложение их не создаёт.

## Установка политики прямого доступа

Приложение **не устанавливает правила самостоятельно**. Сначала генерируем план,
просматриваем, соглашаем и только потом импортируем:

```sh
./dist/MikroCockpit.app/Contents/MacOS/MikroCockpit --policy-plan > policy.rsc
```

Не импортировать `router-setup.example.rsc` вслепую: это пример из публичного
профиля. Сгенерированный план проверяет исходный mark-routing и отсутствие
активного fasttrack, делает backup/export и только затем добавляет свои правила.
Повторный импорт намеренно останавливается, чтобы не плодить дубликаты.
`router-rollback.rsc` удаляет только правила MikroCockpit и возвращает прежний
firewall; созданные вами исключения назначений сохраняются.

Что делает политика: WAN guard-цепочку **перед** `established/related`, которая
пропускает только прямые устройства, назначения из bypass-list и явно указанные
`extra_direct_rules`, затем drop; mangle-исключение для прямых устройств перед
VPN-маркировкой; блок forwarded IPv6 на указанных WAN. Это режим прямого доступа
по IPv4, **не** замена firewall — DHCP/DNS/управление роутером и VPN-транспорт не
затрагиваются.

Таймеры используют `address-list timeout`: работают без приложения и истекают
сами. Постоянные исключения переживают перезагрузку.

## Модель безопасности

- Сетевые операции выполняются одним worker-потоком; event loop macOS не блокируется.
  Перед изменением читается свежий снимок, после — проверяется результат.
  Таймаут означает *неизвестный результат*, автоматического повтора нет.
- Команды RouterOS строятся через единую точку экранирования плюс валидацию
  строк конфигурации; произвольные скрипты не принимаются.
- Веб-сервер слушает только `127.0.0.1` на свободном порту. API требует случайный
  token, мутации дополнительно проверяют `Origin`/`Host`; нет CORS и пропуска CLI.
  Token передаётся в URL fragment и убирается из адресной строки. Строки от
  роутера (имена DHCP-хостов) выводятся как текст, не как HTML.
- Аудит-журнал пишет намерение до действия и результат после.
- Рекомендуется отдельный пользователь RouterOS только с нужными правами
  `ssh/read/write/test`. Ограничения меню — **не** серверные ACL.

## Проверка

```sh
cargo test
cargo clippy --all-targets -- -D warnings
python3 check_web.py       # реальный локальный API в demo-режиме
python3 check_memory.py    # ограниченный RSS при многократной перерисовке меню
./dist/MikroCockpit.app/Contents/MacOS/MikroCockpit --check    # только чтение
./dist/MikroCockpit.app/Contents/MacOS/MikroCockpit --smoke    # demo-трей на 3 с
```

`--check` только читает роутер, `--demo` не выполняет сетевых действий.
Unit-тесты покрывают экранирование CLI, CIDR, guard перед established, WAN-mapping,
запрет nested DIRECT, HTTP auth/Origin/allowlist команд, валидацию портов и
счётчики скорости. Мутации на реальном роутере по-прежнему требуют ручной
проверки после deploy.

CI на каждый push гоняет тесты, clippy, сборку и оба check-скрипта.

## Известные ограничения

Честный список для v0.1 — это и есть «первый релиз грубоват»:

- **Только macOS.** Логика роутера/политики/веба переносимая, но `build.rs` и
  `native/dashboard.m` требуют AppKit, диалоги — через `osascript`, пути
  (`/usr/bin/ssh`, `uuidgen`, `open`) захардкожены. Windows/Linux — в планах, не в
  наличии.
- **Нет notarization, нет установщика автозапуска, сборка под одну архитектуру.**
  Только локальная ad-hoc подпись.
- **Нет интеграционных тестов на реальном роутере** в CI; мутации проверяются вручную.
- **Окно нативных настроек** не умеет drag-reorder разделов трее (веб-панель умеет).
- **Часть проверок структурная, а не поведенческая**: `check_memory.py` и
  `--native-smoke` проверяют рендеринг и память, а не исходы на роутере.
- **Индикаторы доступности интернета — не тест на утечки.** Purple означает
  достижимость плюс активный non-WAN default в заданной VPN-таблице. Проба VPN
  public IP выполняется **на роутере** через `api.ipify.org`.
- **Фокус на IPv4.** Forwarded IPv6 на указанных WAN закрыт политикой, но IPv6 VPN,
  VRF, динамическая маршрутизация и ECMP не поддерживаются.
- **Обработка ошибок местами громкая, а не мягкая**: несколько путей в
  нативном меню используют `expect` — при сбое будет паника, а не деградированный трей.

## Язык интерфейса

Трей, нативные диалоги и дашборд пока только на английском. `src/locale.rs`
определяет предпочтительный язык macOS на старте и откатывается на английский;
язык браузера не может переопределить выбор. Локализация отложена до стабилизации
функциональности.
